{% load i18n static language_menu %}{% comment %} The two corner buttons, the same on every page (LEG-Design-Vorgaben/login/VORGABEN.md, section 5): the language menu and the light/dark button. The language menu is a real form: every language is a submit button that posts to the view set_language (leg_platform/language.py), which sets the language cookie and returns to this page, so it works without JavaScript (the menu opens by hover and focus in CSS). static/js/corner-controls.js only adds the tap behaviour, Escape and the arrow keys; the light/dark button needs it and stays hidden without it. The names of the languages are written in their own language and are not translated. The flags are files of the own origin (Content Security Policy, img-src 'self'). The form has no "next": the view returns to the page by the Referer header (Referrer-Policy same-origin sends it with every request to the own site; Django checks it like "next") and to the start page without it. So the address of the page, which may carry search terms or an unchecked "next" of its own, is never written into the page again (D-054). The menu needs a CSRF token and the route: the 500 page is rendered without a request, so it shows only the light/dark button. {% endcomment %}{% language_menu as menu %}{% url 'set_language' as set_language_url %}
